# Professional Voice

## Purpose

`voice.md` describes the user's professional communication style for job-search writing. It is not a broad personality file. Keep it practical: what to say, what to avoid, and which expressions sound like the user.

## Suggested File Shape

```md
# Voice Profile

## Universal Rules
- Prefer concrete evidence over broad self-promotion.
- Avoid exaggerated enthusiasm.

## English Professional Voice
- Plain, concise, engineering-oriented.
- Avoid polished corporate phrases.
- Use direct fit statements.

## Chinese Professional Voice
- Concise and direct.
- More like professional chat than a translated cover letter.
- Avoid formal set phrases.

## Confirmed Voice Rules
- ...

## Observed Signals
- ...

## Avoid
- ...

## Preferred Examples
- ...
```

## Onboarding

Do not ask the user to write `voice.md` from scratch. Use an interactive flow:

1. Infer observed signals from resumes and existing conversation.
2. Offer A/B/C style choices for openings, fit statements, enthusiasm level, and personal background.
3. Ask why the user prefers a choice when the reason matters.
4. Propose concrete voice updates.
5. Write only confirmed rules after user approval.

Ask one question at a time. Provide a recommended answer for style and positioning questions.

## Feedback Learning

When the user says a draft sounds wrong, convert the critique into a candidate voice rule:

```text
Suggested voice update:
- Avoid sales-like claims such as "I can bring immediate value."
- Prefer concrete fit statements over self-promotional promises.

Save to voice.md?
```

If feedback is specific to one company or one situation, store it as an application note artifact instead of a long-term voice rule.
